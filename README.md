# Mii Creator (open source)

The full Mii Creator web app from [mii.nxw.pw](https://mii.nxw.pw): the editor, library, renders, QR codes, 3D export and all 14 shader styles. It runs entirely on your own machine or on GitHub Pages.

The code is split into readable source files instead of one minified bundle, so you can find what you need and change it: a shader, a hat, a colour palette, a translation, a setting.

- **Run it locally:** [Quick start](#quick-start)
- **Put it online:** [GitHub Pages](#deploying-to-github-pages)
- **Change or add things:** [docs/adding-content.md](docs/adding-content.md)

## Quick start

You need [Node.js](https://nodejs.org) 18 or newer. No `npm install` is needed: nothing outside Node itself is used.

```sh
node server.js          # or: npm start   (Windows: start.bat, macOS/Linux: ./start.sh)
```

Open http://127.0.0.1:8080. Your library is saved in `data/db.json`.

While you edit code, run `node server.js --watch` (or `npm run dev`). It rebuilds every time you save a file in `src/`; reload the page to see the change.

| Command | What it does |
|---|---|
| `node server.js` | Builds `public/dist/main.js` if `src/` changed, then serves the site |
| `node server.js --watch` | Same, and rebuilds whenever you save a file in `src/` |
| `node server.js --port=3000 --host=0.0.0.0` | Another port, reachable from other devices |
| `node tools/build.js` | Only build `public/dist/main.js` |
| `node tools/build-static.js` | Build the GitHub Pages version into `dist-static/` |

## Project layout

```
src/                     the app's source code (this is what you edit)
  manifest.json          the order the files are joined in
  app/                   Mii Creator's own code
    main.js              entry point
    mii/                 the Mii class, colour palettes, file formats (.miic, FFSD, CharInfo, Studio)
    editor/              the editor screen and one file per editor tab
    shaders/             the 14 shader styles + shader-registry.js
    renderer/            building the 3D Mii (head, body, hats, outfits), cameras, the 3D viewer
    assets/              loading model bundles and textures
    items/               hat / accessory / outfit lists
    settings/            every setting and the Settings dialog
    library/ dialogs/    library screen, create/export/render/share dialogs
    ui/                  Html helper, modals, tabs, icons, notifications
    ...
  shaders/               GLSL for every shader (.vert.glsl / .frag.glsl)
  data/                  big tables as JSON (hat model info, colour tables, expressions, ...)
  vendor/                third-party libraries (three.js, JSZip, SortableJS, ...), kept as bundled
public/                  everything served as-is: HTML, CSS, images, models, sounds, FFLRes*.dat
  dist/main.js           built from src/ (not committed — generated by the build)
server.js                local server: static files + /api emulator + auto-build
lib/api-core.js          the /api/library emulator (shared by server.js and the static build)
lib/debug-flags.js       hidden "custom asset" switches (see config/debug-flags.json)
tools/build.js           joins src/ into public/dist/main.js
tools/build-static.js    makes the GitHub Pages version
.github/workflows/       GitHub Pages deployment
```

## How the build works

`tools/build.js` joins the files listed in `src/manifest.json` into a single `public/dist/main.js`, in that order. It also pastes in the GLSL and JSON files that the code references with `includeGLSL("...")` and `includeJSON("...")`.

The files share one scope, just like the original bundle, so a function defined in one file can be used in any file that comes after it. Every source file starts with a header that says what it defines and which other files it uses, so you can follow a name to where it lives.

There's no transpiling, minifying or npm. What you write is what runs.

## Deploying to GitHub Pages

1. Push this repository to GitHub.
2. Go to **Settings → Pages → Build and deployment** and set **Source** to **GitHub Actions**.

`.github/workflows/main.yml` builds and publishes the site on every push to `main`. It works at `https://<user>.github.io/<repo>/`; the build rewrites links for that sub-path automatically. It also works on a custom domain.

GitHub Pages can't run `server.js`, so on the hosted site each visitor's library and Personal Mii are saved in their own browser. Use the library's export and import to move Miis between browsers or devices.

## About the code

The original app was published as one minified bundle. Here it has been split back into files and the important names have been restored, including:

- shaders and materials (`TomodachiLifeShaderMaterial`, `getShaderMaterialClass`);
- data formats (`Mii`, `MIIC_STRUCT`, `FFSD_STRUCT`);
- editor tabs (`hatTab`, `TAB_HAIR`);
- palettes (`COMMON_COLORS_HEX`);
- settings (`SETTINGS_SECTIONS`, `getSetting`);
- three.js classes (`Vector3`, `WebGLRenderer`, ...);
- UI helpers (`Html`, `Modal`, `Notify`).

Local variables inside functions are still short (`e`, `t`, `r`), and so are some deeper internals. Third-party code in `src/vendor/` is left as bundled.

The joined result is checked to be the same program as the original build. Two changes were made on purpose:

- the old host-lock check is gone;
- the hair-tip typo in the Tomodachi Life and No Lighting shaders is fixed (`col.rgb` → `color.rgb`).
